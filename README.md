# «Агенты» — пиксельный мультик, полностью посчитанный кодом

45 секунд, 16:9, 1920×1080, 30 fps, H.264 + AAC. Каждый кадр и каждый звук — результат
программы: без видеоредактора, без генерации картинок, без сэмплов. В кадре только
спрайт героя (`footage/character/`) и бренд (`footage/brand/`), всё остальное нарисовано кодом
пиксель за пикселем в той же сетке.

## Сборка — одна строка

```bash
npm run build
```

Это `node tools/build.js`:
1. синтезирует саундтрек → `out/audio.wav`;
2. считает 1350 кадров параллельно в `worker_threads`;
3. по порядку отдаёт их в ffmpeg → `out/film.mp4`.

На 16-поточном CPU (Ryzen 7 8845HS) полная сборка занимает около 40 секунд: звук — пара секунд, 1350 кадров 1920×1080 — ~38 кадров/с. Нужны Node ≥ 20 и `ffmpeg` в PATH; npm-зависимостей нет.

Проверка QR в готовом MP4 (Python через uv, в систему ничего не ставится):

```bash
npm run qr
```

Остальные команды:

| Команда | Что делает |
|---|---|
| `node tools/contact.js [s01 … s16 \| film]` | контакт-листы в `out/sheets/`: тайл на каждую восьмую внутри сцены + лист всего фильма |
| `node tools/mp4sheet.js` | проверка готового MP4 (кадры декодируются из файла): пары кадров на каждой склейке, 48 кадров по фильму, последний кадр 1920×1080 |
| `node tools/diffscan.js` | скан движения готового MP4: самые большие скачки между соседними кадрами (склейка или задуманный удар) и однокадровые «выскоки» |
| `node tools/frame.js 12.5 b5.3 f120 --size 1920x1080` | отдельные кадры в `out/frames/`: по секундам, по такту/доле, по номеру кадра |
| `node tools/build.js --no-audio --frames 225:450 --size 960x540 --out out/test.mp4` | быстрый частичный рендер |
| `npm run audio` | только звук |
| `npm run player` | HTML-плеер: `http://localhost:8080/player/` |

## HTML-плеер (бонус)

`player/` проигрывает тот же фильм прямо в браузере. Это не видеофайл: работает тот же код.
- Кадры считает пул module-воркеров тем же `src/film.js`.
- Звук синтезирует воркер тем же `src/audio/score.js`.
- Часы воспроизведения ведёт аудио, а кадры считаются с упреждением.
- Есть перемотка, пауза (пробел), покадровый шаг (←/→) и выбор разрешения рендера.

## Структура кода

```
src/
  timeline.js        сетка 128 BPM, таблица 16 кадров, CUES — все точки синхронизации (по ним живут и картинка, и звук)
  story.js           непрерывность: состояние комнаты как чистая функция времени (часы, прогресс, дождь, рассвет,
                     краска, кружка, кофейная река, искры, лампа, гирлянда, экран монитора)
  film.js            время → кадр → арт-картинка → камера → выходной кадр (без Node API, работает и в браузере)
  engine/
    art.js           арт-холст: слои albedo / emissive / tag, примитивы в целых арт-пикселях, дизеринг Байера
    light.js         свет: albedo × свет + эмиссия + свечение; ступенчатые полосы с узкой дизер-кромкой,
                     персонажи освещаются целиком (без шума на лицах) + контровой пиксель
    camera.js        камера: зум 1 → nearest neighbour с субпиксельным сдвигом, иной зум → суперсэмплинг 4×4
    font.js          пиксельные шрифты 3×5 и 5×7 (латиница, цифры, нужная кириллица)
    color.js util.js png.js
  assets/
    hero.js          герой из канонического спрайта 24×45: глаза-эмоции, руки-«марионетки» (указать, дирижировать,
                     нажать Enter), вид со спины, шаги
    bots.js          четыре агента, процедурно, в сетке героя и в цветах кольца логотипа
    room.js          декорация: одна комната 320×180 (окно с городом и дождём, стол, монитор, стикеры, гирлянда,
                     лампа, удлинитель, кофейная река), экран монитора в режимах terminal / code / glitch / boot /
                     progress / deployed
    brand.js         QR 25×25 и логотип-глаз 70×39, перенесённые в арт-сетку из footage/brand
    load-node.js     загрузка ассетов в Node (в браузере — player/assets.js)
  scenes/
    s01.js … s16.js  16 кадров; каждый — чистая функция render(t) → { img, w, h, cam }
    common.js        общие инструменты кадра: composeRoom, lightRoom, камера, огибающие, IK рук, эффекты
    blocking.js      мизансцена: где стоит каждый персонаж (стыки кадров совпадают)
    intro_lib.js     спавн (кадры 1–3)          chaos_lib.js      цепная реакция (4–7)
    dark_lib.js      замыкание и темнота (8–10) conductor_lib.js  дирижёр и монтаж (11–12)
    dawn_lib.js      ракета, окно, небо, подоконник (13–15)
  audio/
    synth.js         DSP: осцилляторы PolyBLEP, фильтры TPT/ZDF, реверб, дилей, лимитер
    voices.js        инструменты и все звуковые эффекты
    score.js         партитура: всё расставлено по CUES, мастер-шина
    render.js        Node-обёртка → out/audio.wav
tools/  build.js worker.js pool.js contact.js frame.js mp4sheet.js diffscan.js qr_check.py serve.js
player/ index.html player.js frame-worker.js audio-worker.js assets.js
```

Детерминизм обеспечен так:
- `Math.random`, `Date` и состояние между кадрами не используются;
- случайность — только через `hash()` и шум от координат и времени;
- кадр n берётся в середине своего интервала, `t = (n + 0.5) / 30`.

Поэтому кадры считаются в любом порядке и параллельно, а два рендера дают бит-в-бит одинаковый звук.

## Принятые решения

**Холст 320×180, масштаб ×6.**
- Герой высотой 45 px занимает четверть высоты кадра. Общие планы с героем, четырьмя ботами, столом и окном помещаются в кадр 1:1.
- Крупные планы делает камера: зум с суперсэмплингом 4×4.
- При 240×135 персонажи вышли бы слишком крупными для общих планов, при 480×270 — мелкими и «пустыми».
- Шрифт 3×5 при ×6 даёт буквы 18×30 выходных пикселей, это читаемо.
- QR в концовке — 2×2 арт-пикселя на модуль при статичном зуме ×2, то есть 24×24 выходных пикселя на модуль.

**Одна декорация, разные камеры.**
- Вся комната — один мир 320×180. Кадры отличаются камерой, светом и состоянием из `story.js`.
- Поэтому последствия цепной реакции сохраняются между склейками: где упала кружка, куда течёт река, какого цвета стены.

**Театральная условность.**
- Монитор повёрнут к зрителю, герой сидит за столом лицом к нам, окно у него за спиной.
- Так в одном кадре читаются лицо, экран с часами и стикер-дедлайн — хук.

**Кружка падает на пол.**
- Кодер сталкивает кружку со стола — так в раскадровке. Значит, Бариста наливает уже в кружку на полу, и кофейная река течёт по полу к удлинителю.
- В раскадровке река текла «по столу на пол»; поменялась география, причинная цепочка та же.

**Ноты и цвета ботов.**
- Бариста — C3, бас, оранжевый.
- Кодер — E4, арпеджио, синий.
- Дизайнер — G4, мелодия, маджента.
- Тестер — C6, «тинь» и ударные, зелёный.

Как ноты работают по ходу фильма:
- Цвета — сегменты кольца логотипа.
- Вместе ноты дают аккорд рассвета C-E-G-C.
- При спавне у каждого ноту видно: цветная вспышка, кольцо и ♪ в его цвете. В темноте та же пара «цвет + нота» отыгрывается, когда герой показывает на бота.
- Тестер (высокое C) в темноте не пикает: его нота замыкает аккорд в момент «идеи».

**Свет.**
- Модель: albedo × свет + эмиссия + свечение.
- Спад света квантуется в чистые полосы с узкой дизер-кромкой Байера, как ручное пиксельное затенение.
- Персонажи освещаются целиком по центру спрайта, плюс 1-px контровой свет со стороны главного источника. Иначе на лицах появляется шум дизера.
- Свет монитора не падает на сам монитор.
- Свечение только от ярких эмиссионных пикселей, ступенчатыми ореолами.

**Руки героя.**
- Руки-«марионетки» рисуются рукавом той же толщины, что у спрайта: 5 px ткани у ближней руки и 3 px у дальней, плюс контур, манжета и кисть-варежка.
- Длина — `ARM_SCALE` = 0.74 от номинальной длины, которую задаёт кадр. Поднятая или вытянутая рука выходит не длиннее собственной опущенной руки спрайта.
- Позы сохраняют углы. IK к конкретной точке (например, палец на Enter) идёт через `reachIK`: цель пересчитывается под укороченную руку.

**Камера.**
- Панорамы при зуме 1 — чистый nearest neighbour: весь кадр сдвигается шагами по 1 выходному пикселю, то есть на 1/6 арт-пикселя.
- Любой другой зум — суперсэмплинг 4×4 всего кадра.
- Whip pan — быстрый проезд камеры со сплошными пиксельными линиями скорости.

**Звук.**
- Тот же `CUES` — единственный источник времени для картинки и звука.
- Громкость −15.3 LUFS, true peak −1.9 dBTP, клиппинга нет.
- В блэкауте (19.22–20.63 с) и в склейке в чёрное (40.78–41.25 с) — ровные цифровые нули.

**Правки сетки по итогам звука.**
- Искры отстают от последнего удара молоточка на 1/32 (сначала причина, потом следствие).
- Ракета стартует на полдоли позже удара `deployed`, чтобы финальный аккорд успел прозвучать.

## Процесс

- Движок, декорацию, персонажей, непрерывность, пайплайн, кадры 1–3 и плеер я писал сам.
- Саундтрек писал отдельный агент.
- Кадры 4–16 делали четыре параллельных агента по группам: 4–7, 8–10, 11–12, 13–16. У них был общий API (`common.js`, `blocking.js`, `story.js`) и запрет трогать общие модули.
- Каждый кадр проверялся глазами по контакт-листам (тайл на каждую восьмую) и по полноразмерным кадрам на точках синхронизации. Потом шли лист всего фильма, просмотр готового MP4 и проверка QR.
- Правки после первого просмотра:
  - руки героя стали толще и короче, как у спрайта;
  - на подоконнике спиной к нам герой теперь сидит: ноги свешены наружу, видно сиденье на выступе;
  - QR больше не «выплёвывается» пачками из зрачка, а плавно проявляется на месте. Восемь стуков в звуке заменены мягким «потоком пикселей» — тем же мотивом, что при спавне ботов.

## Что получилось

- **Проверки готового `out/film.mp4`.**
  - Файл: 1920×1080, H.264 yuv420p bt709, 30 fps, AAC 48 кГц стерео. Ровно 1350 кадров, видео и звук по 45.000 с, оба начинаются с нуля.
  - QR готов на сильную долю такта 24 (43.125 с). Он читается OpenCV из MP4 на всех проверенных кадрах с 43.17 с до последнего: в полном размере, в половинном и в оттенках серого. В тексте — `https://t.me/p_by_p`.
  - Автоматический скан всех соседних пар кадров (`tools/diffscan.js`) не нашёл ни одного однокадрового «выскока». Все большие скачки приходятся на склейки или на задуманные удары в сетке: лавина кода, розовый «панч», искры, замыкание, склейка в чёрное.
  - Звук в AAC: пик −2.4 dBFS, средняя громкость −16.7 dB, клиппинга нет.
- **Структура из задания.**
  - Хук: Enter на 1.875 с — кадр 56, сильная доля второго такта.
  - Все 15 склеек стоят в сетке. Стыки проверены по парам кадров прямо из MP4.
  - Часы видны на экране: 02:00 → 04:30 (вспыхивает на мониторе в хаосе) → 05:59 → 06:00.
  - Цепочка причин: код → кружка → кофе → краска → удлинитель → замыкание.
  - Подвеска и оплата: цвет и нота каждого бота — при спавне, в темноте и при дирижировании.
  - Кнопка «v2 · ДЕДЛАЙН 08:00» и сразу склейка в чёрное.
- **Одна плотность пикселей.** В каждом кадре декорация, реквизит, эффекты и текст нарисованы в сетке спрайта героя. Зум камеры меняет размер пикселя на экране у всего кадра сразу.
- **Плеер.** HTML-плеер считает те же кадры и синтезирует тот же звук в браузере. Проверен на всех 16 кадрах.

## Что не получилось или вышло слабее

- **Мелкие персонажи на общих планах** (хаос, дирижёр). Герой — 45 px на 180 px высоты кадра. Действия читаются по вспышкам, кольцам и нотам, а мимика там почти не видна.
- **Кадр 5** снят низко: верхнюю половину кадра занимает фронт стола.
- **Дизайнер не умеет смотреть влево:** кисть всегда у него справа. Броски вверх-влево идут поперёк тела.
- **Кадр 6:** стены перекрашиваются шторкой слева направо, а не от точки удара.
- **Кадр 11:** на реплике дизайнера герой показывает палочкой поперёк себя, потому что палочка остаётся в той же руке, что и в кадре 10.
- **Кадр 12:** прыжок тестера на монитор без линий движения, выглядит немного «парящим».
- **Розовая река** в такте 15 (бариста её выпивает) малоконтрастна на розоватом полу. Бегущие блики помогают, но она всё равно тихая.
- **Движение** я проверял по кадрам: контакт-листы, стыки прямо из MP4, скан разниц, плеер. Просмотра в реальном времени глазами не было.
- **Ошибки в общем коде**, найденные при сборке и исправленные:
  - солнце вставало раньше рассвета;
  - блики реки не бежали из-за отрицательного остатка от деления;
  - открывание окна и стикер v2 в декорации рисовались сломанно — теперь их рисуют сами кадры 13 и 15, мёртвый код удалён;
  - на контакт-листах последний тайл сцены показывал первый кадр следующей.
